# ADR-009: Lambda Serverless Backend Cutover Delivery

## Status

Accepted

## Context

The backend migration to Lambda needs a deployment path that preserves the current chatbot behavior while removing the always-on backend runtime. The delivery slice must package the existing FastAPI/Mangum backend, validate staging through API Gateway HTTP API, promote the same immutable package to production, and keep Lambda-version rollback available.

The EC2 Compose/Cloudflare Tunnel production path had no real data and was intentionally removed from the production Terraform root before final apply. Production no longer requires VPC, public subnet, Cloudflare account ID, or tunnel secret inputs. Current custom-domain DNS still uses a Cloudflare zone ID and local Terraform provider token when Terraform manages ACM validation and backend CNAME records; those are DNS management inputs, not Cloudflare Tunnel or Lambda runtime requirements.

## Decision

Use GitHub Actions to build one scanned Lambda package artifact, deploy it first to an isolated staging Lambda alias, validate the direct staging endpoint, then promote the same package hash to the production Lambda alias. Production Terraform is Lambda-only and the legacy EC2 Compose deploy job is removed.

`.env.deploy` remains a local/manual input only. Lambda runtime secrets come from SSM Parameter Store or Secrets Manager references authorized by IAM; no committed env files or static AWS keys are allowed in packages or workflows.

## Details

| Topic | Decision |
|---|---|
| Production boundary | API Gateway HTTP API -> Lambda alias. |
| Package promotion | The package SHA from `lambda-package` must match before staging and production deployment. |
| Staging validation | Direct non-production URL must pass `/health`, authenticated `/chat`, File Inputs/source docs, DynamoDB persistence, IAM-denied probe, and production URL isolation. |
| Rollback | Capture the previous production alias target before promotion and restore it with `scripts/lambda_rollback.py` if smoke fails. |
| EC2 fallback | Removed as an approved destructive cutover; no EC2 route rollback is available. |
| Session policy | No live EC2 sessions exist, so no export/drain is required; cutover may reset in-memory state. |
| Custom-domain DNS | Terraform may manage Cloudflare DNS for API Gateway custom-domain records; this does not restore Cloudflare Tunnel. |

## Consequences

### Positive

- Production promotion is tied to the exact package that passed staging smoke and evaluation.
- Rollback target discovery is explicit before alias movement.
- Staging cannot silently call production URLs.
- Runtime secrets stay outside the repository and Lambda zip.
- Production Terraform can plan/apply without `TF_VAR_vpc_id`, `TF_VAR_public_subnet_id`, or `TF_VAR_edge_tunnel_secret`; Cloudflare zone/token inputs are only needed when managing custom-domain DNS through Terraform.

### Negative

- Direct Lambda code updates can drift from Terraform's package filename metadata until the next infrastructure reconciliation.
- Staging smoke depends on configured GitHub variables/secrets and live AWS permissions, so missing values fail the workflow rather than being inferred.
- Rollback is limited to the previous Lambda alias version; EC2 Compose is no longer a production fallback.

### Future work excluded

- WAF/API Gateway advanced throttling.
- SQS/EventBridge/Step Functions workflow redesign.
- Async chat job architecture for slow File Inputs.
- Dashboards, alarms, X-Ray, and OpenTelemetry.
